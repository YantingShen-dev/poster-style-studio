# 风格要素与编辑单位

参考图拆解的目标是让协作者用少量自然动作继续设计，不是让每处可见边缘都成为独立图层。先找出最影响辨识度的结构，再写下用户下次制作同系列海报时会做什么：换一句话、换一张图、拖入一个装饰、改纹样密度，还是重排内部几何。默认选中单位以这些动作为准；内部仍由标准工程对象构成。

| 编辑单位 | 适合的信号 | 默认操作 | 深入编辑 |
| --- | --- | --- | --- |
| 基础对象 | 单独移动、改色或描点的形状与文字 | 直接选中并修改 | 钢笔节点、文字框等通用能力 |
| 普通贴纸 | 可多次拖入、主要改大小／颜色／位置的独立图像或角色 | 缩略图插入独立副本，整体选中 | 双击进入子对象，必要时解组 |
| 特殊贴纸 | 可重复使用，且每一份都需要少数造型参数的图像或结构 | 整体插入、移动，并调当前副本的专属参数 | 双击查看和修改内部路径；解除生成关联后允许自由重画 |
| 信息组件 | 外框、装饰与内容一起复用，如窗口、终端、票券、标签或卡片 | 整体选中、缩放、复制；直接改标题、正文、图片槽位及常用外观 | 双击进入组内调按钮、边框、路径；默认改字不要求先找子图层 |
| 生成系统 | 点阵、放射纹、线路、重复排布等由规则共同决定的主体 | 保持一个可识别的顶层单位，用少数高价值参数实时探索 | 展开内部图层，单独微调或转为普通对象 |

“贴纸”与“组件”不是互斥分类。一个带标题和内容槽位的框可以放在贴纸库里作为模板；插入后仍以整个框为默认选中单位，同时提供该实例的填字属性。普通贴纸只需通用变换；特殊贴纸必须解释参数怎样改变造型。不要为了满足统一工程模型而把一个面向用户的整体拆成大量平级散件。

## 决定边界

对最重要的少数风格要素，逐一检查：

1. **识别作用**：拿掉它，海报是否仍像同一套设计？辨识度高的要素优先获得专属入口。
2. **变化频率**：同系列作品中，用户最可能改的是内容、局部形状，还是生成规则？把高频变化放在外层；低频细节留给组内编辑。
3. **重复方式**：是复制一个完整结构，还是把零件重新拼搭？前者保留整体组件，后者提供独立贴纸／基础形状。
4. **参数价值**：参数要能明显改变视觉，并有可理解的名称、范围和初始值；不要仅因为能暴露算法变量就增加滑杆。
5. **保真边界**：原图无法可靠还原的细节可保留位图或固定轮廓，但不能把重要的填字入口藏在位图或散件中。

若两种拆法都合理且会改变工作台用途，向用户简短描述各自的日常操作并询问。没有回复时，对高频信息容器默认整体加可改槽位；对可重复主体默认普通贴纸；对有明确生成规律的纹样默认参数化系统。深层路径编辑始终作为可进入的补充，不替代外层语义操作。

## 落地与验收

用 `group` 作为复杂单位的选择根，子层保持标准对象。组件的文字／图片槽位和特殊贴纸参数必须属于**当前实例**，随工程保存、复制、撤销和再次打开；不能用一个全局 `style.params` 控制全部副本。一个简单的项目内约定是给组根保存纯数据 `styleUnit:{kind,version,params}`，给可替换的子对象保存 `styleSlot`（例如 `title`、`body`、`image`）；复制后按当前组的子对象查找槽位，不跨实例引用固定对象 ID。底座会保留这些额外 JSON 字段，但专属扩展须校验它们、实现当前实例的属性区和更新事务；这不是底座预置的通用组件面板。不建立与工程脱节的 DOM 装饰层。更新几何时保留根对象与可匹配子对象的 ID、人工变换和新增内容，并说明哪些手工节点会被重新生成覆盖。

规则纹样的关键滑杆应在拖动时预览，松开形成可撤销的一步；较重的计算可以按帧合并，不能要求用户每改一个数都点“生成／更新”。颜色、文字或来源图片的变化应沿用相同的预览画面和导出数据。动态预览与逐帧导出共用参数及时间采样。

交付前完成一个实际任务，而不只点按钮：复制信息组件并改第二份标题和正文，第一份不变；插入两份特殊贴纸，只改其中一份参数；拖动纹样关键滑杆，画布即时变化，松开后一次撤销可恢复；再保存、打开工程，确认整体与内部编辑入口都在。
